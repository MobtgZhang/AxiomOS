# 并发与资源所有权

BSP 负责内核初始化、物理页分配、VFS、进程管理及顺序用户程序运行。AP 在独立栈上进入常驻工作循环，可以通过 `SMP.Work` 提交内核任务。当前没有抢占、用户线程迁移、跨核用户调度或 TLB shootdown；每 CPU 运行队列提供有界策略数据结构，尚未连接硬件抢占路径。

## 内核同步结构（AxiomOS.Sync）

`AxiomOS.Sync` 是通用包，对四个 HAL 原语实例化：`Number`（地址转整数）、`Compare_Exchange`、`Fetch_Add`、`Pause`。宿主测试用纯 Ada 替身实例化同一份逻辑；内核经 `AxiomOS.Kernel.Locks` 绑定真实架构原子操作。每个原语只操作一个对齐 32 位字，并带 acquire/release 屏障语义。

- **票据自旋锁（Spinlock）**：Acquire 发放单调递增票据并忙等到 grant 计数到达本票，等待者按 FIFO 次序进入，而非在单字上竞逐。两个计数都是原子字。
- **互斥锁（Mutex）**：带所有者追踪的锁。持有者用调用者选择的令牌标识（如 CPU 编号），只有持有者能释放；递归获取返回 Invalid_Argument 而不是死锁，他人释放返回 Permission_Denied。尚无阻塞调度器，Acquire 忙等；Acquire/Try_Acquire/Release 拆分使未来等待路径可替换而不动调用者。
- **计数信号量（Semaphore）**：固定最大值的计数。Up 归还单位（超出最大值返回 No_Space），Down/Try_Down 消耗单位；Try_Down 在空时返回 Would_Block，不会自旋。

HAL 原子操作的每架构实现位于 `arch/<isa>/cpu.S`：x86-64 用 `lock cmpxchg` / `lock xadd`；AArch64 用 LSE `casal`/`ldaddal`（无 LSE 时退回 LL/SC）；RISC-V 用 `lr.w.sc.w` 循环，`sc.w` 以 rd 为零表示成功；LoongArch 用 `ll.w.sc.w` 循环，**`sc.w` 把 LLbit 写入 rd——1 表示成功、0 表示失败，与 RISC-V 相反**（该约定曾致取加循环死循环、CAS 误报，已修正并经 QEMU 验证）。

验收：内核自测 `AXIOM:SYNC:PASS`（四架构 QEMU）覆盖自旋锁两轮 Acquire/Release、互斥锁的冲突/递归/外人释放、信号量的上限与清空路径；宿主测试 `test_sync` 以替身原子操作在 65536 单元存储上验证同一逻辑。忙等只在 QEMU 一致性多核上验证，尚未覆盖真实硬件内存序或中断打断自旋的路径。

## AP 工作与锁

`SMP.Locks` 使用 HAL 原子交换及 acquire/release 屏障。每 CPU 邮箱由独立自旋锁保护，状态依次为 Idle、Pending、Executing、Finished；回调在释放邮箱锁后运行。每个 AP 只允许一个未收取任务，重复提交返回 Busy。票据携带 CPU 编号和代次，Collect 成功收取后旧票据失效；代次耗尽后拒绝继续分配。Wait 超时只停止等待，不取消任务，也不释放任务参数。调用者必须保证参数和回调持续有效，直到任务被收取。

CPU 启动上下文与栈在发出启动请求后保持分配；即使握手超时，迟到 AP 仍可能访问它们。当前不支持 CPU 下线。拓扑发现属于 `platform/`；INIT/SIPI、PSCI、SBI HSM、IOCSR 及启动汇编属于 `arch/`；枚举、超时、握手和工作策略属于公共 Ada 层。

启动验收包含两轮共享锁计数、邮箱背压、旧票据拒绝，以及等待超时后再次等待成功。两轮总计数为 `4000 * (CPU_Count - 1)`。AP 在这些测试后继续等待工作，并参与 BSP/AP 并发块读取。

## 管理对象与 DMA

物理分配器、堆、进程表、VFS/挂载表及句柄表要求调用者串行访问；当前由 BSP 独占。不能从 AP 回调或中断上下文直接操作这些对象。跨核启用它们前需要增加相应锁及锁顺序；设备中断还需要保存/恢复中断状态的锁。

VirtIO Block 的同步读取由队列锁串行化，允许多个 CPU 调用 Read，每次只有一个请求在途。提交与完成处使用 HAL 屏障。超时或完成环损坏后拒绝后续读取，保留 DMA 缓冲，避免设备仍在访问已回收页。Shutdown 取得队列锁并请求设备复位，只有确认设备状态归零后才释放 DMA 页；复位超时保留所有权。驱动生命周期 Stop 失败不解除资源占用，Running/Failed 设备不能直接 Remove。初始化/生命周期控制由 BSP 串行执行；不能与 Read 并发重新初始化队列锁。

这里尚未提供非一致性 DMA 缓存维护、IOMMU、多队列或异步取消。当前支持范围是四个 QEMU 平台的一致性 DMA。

## 页表与用户资源

页表创建失败回收已挂入树的表页；动态映射失败会清除成功及部分创建的路径并回滚数据页和映射记录。Unmap 在回收数据页前完成局部 TLB 刷新，Protect 在开放执行权限前调用 ISA 指令缓存维护接口。页表叶查询与修改只通过 HAL，通用地址空间层负责范围、配额、W^X 和所有权。

用户根页表只在 BSP 上使用。AP 保留各自启动时的映射，不访问用户根；这不能推广成同一地址空间可在多个 CPU 同时运行的保证。用户 Copy 在执行前验证整个范围，再逐映射复制，不要求物理页连续。BSP 在 syscall 执行期间独占当前地址空间，没有并发解除映射。

销毁页表只回收表页，进程映射记录拥有用户物理页。退出或异常先关闭所有句柄；切回内核根后销毁用户页表、回收数据页，再回收进程槽。失败装载、正常退出和三种故意用户异常均检查可用页数。打开与复制句柄增加 VFS 节点引用；关闭和退出减少引用。存在打开引用或子挂载时 Unmount 返回 Busy。

系统调用/异常使用独立 256 KiB 内核栈，容纳有界 VFS/存储调用帧；当前没有内核栈保护页或运行时栈探针。不能据此允许任意递归或无界调用深度。

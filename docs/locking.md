# 并发与资源所有权

当前执行模型是 BSP 完成内核初始化和顺序用户程序运行；AP 启动后参加有界共享计数测试，然后停止等待。存在每 CPU 运行队列数据结构，但尚无抢占、线程迁移、跨核调度和 TLB shootdown。

`SMP.Locks` 的自旋锁使用 HAL 的原子交换和 acquire/release 所需屏障；各 ISA 提供实际指令。AP 发布 online/completed 标志后，BSP 通过原子/易变访问等待并验证握手身份。每个 AP 与 BSP 各递增 1000 次，最终计数必须等于 `2000 * (CPU_Count - 1)`。QEMU 验收还独立核对 AP online 日志数量。

物理页分配器、显式堆、进程表、VFS/句柄表和 VirtIO 队列目前要求调用者串行访问。它们没有通过在内部任意加锁来提供并发保证。启用跨核调度前，需要定义这些对象的锁及顺序；启用设备中断前还需要区分普通自旋锁和保存/恢复中断状态的锁。当前不得从中断上下文或多个 CPU 同时调用这些管理接口。

VirtIO Block 当前只有单个同步队列，每次最多一条在途请求。DMA 页保持内核所有权；设备完成后才读取状态和数据，提交与完成处执行 HAL 屏障。超时后将设备标记为不可继续使用，避免覆盖设备仍可能访问的 DMA 缓冲。设备复位恢复、请求取消、多队列和非一致性 DMA 缓存维护尚未实现。

页表创建失败要销毁已挂入树的中间表并返回零 root；销毁只回收页表页。用户物理页由进程的映射记录拥有，在切换回内核页表后分别回收。映射记录建立失败时，装载器仍持有新分配的数据页并负责释放。进程装载失败会关闭句柄、退出并回收进程槽；正常退出及隔离异常路径也核对空闲物理页数，避免只验证进程状态而遗漏内存泄漏。

当前内核在单核内切换硬件页表，局部 TLB 维护由 ISA 后端完成。AP 停止等待后不访问新建用户地址空间；这一前提不能用于未来允许同一地址空间在多核并发运行的设计。
